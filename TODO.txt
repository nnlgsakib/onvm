# ONVM Production Readiness - Critical Issues and TODOs

## CRITICAL SECURITY ISSUES

### 1. Cryptographic and Authentication Flaws
- **CRITICAL**: No signature verification for incoming network messages 
- **CRITICAL**: Node ID to PeerId conversion is simplistic and potentially invalid (consensus/mod.rs:339)
- **HIGH**: Ed25519 keys stored in hex without encryption on disk
- **HIGH**: No access control or authentication for RPC endpoints
- **HIGH**: No rate limiting on RPC endpoints or network operations

### 2. Network Security
- **CRITICAL**: mDNS enabled by default - attack vector in production
- **CRITICAL**: No TLS encryption for libp2p connections (noise protocol config incomplete)
- **HIGH**: No peer reputation or scoring system for malicious behavior
- **HIGH**: No DoS protection mechanisms
- **HIGH**: Bloom filter implementation may have false positives leading to data leakage

## RELIABILITY AND FAULT TOLERANCE

### 3. Data Consistency Issues
- **CRITICAL**: No proper transaction handling in storage operations
- **HIGH**: Race conditions in job state updates (job_scheduler.rs)
- **HIGH**: No atomic commit/rollback for multi-step operations
- **HIGH**: Blob reconstruction can fail silently with partial data
- **MEDIUM**: No data validation before persistence in many places

### 4. Error Handling and Recovery
- **CRITICAL**: Many `unwrap()` calls that can crash the node
- **CRITICAL**: No proper circuit breaker pattern for external dependencies
- **HIGH**: Insufficient error context throughout the codebase
- **HIGH**: No graceful degradation mechanisms
- **MEDIUM**: Limited retry mechanisms with exponential backoff

## PERFORMANCE AND SCALABILITY

### 5. Memory and Resource Management
- **CRITICAL**: No memory pooling for frequent allocations (chunks, WASM execution)
- **CRITICAL**: Large blobs loaded entirely into memory (blob_store.rs:96-128)
- **HIGH**: No streaming support for large file transfers
- **HIGH**: Inefficient serialization using bincode in many places
- **MEDIUM**: No garbage collection for unused/chunked data

### 6. Database and Storage
- **CRITICAL**: Sled DB used without proper configuration or tuning
- **HIGH**: No database connection pooling or management
- **HIGH**: No data compaction or cleanup strategies
- **HIGH**: Storage indices not optimized for query patterns
- **MEDIUM**: No backup/restore mechanisms

### 7. Network Performance
- **CRITICAL**: Synchronous blob fetching blocks event loop (consensus/mod.rs:602-711)
- **HIGH**: No connection pooling or multiplexing optimization
- **HIGH**: Inefficient gossip message deduplication using VecDeque
- **MEDIUM**: No bandwidth throttling or QoS controls
